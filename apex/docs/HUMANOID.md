# APEX humanoid

The face button in the bottom dock switches between the existing core HUD and the supplied humanoid renderer. The choice is saved on this device; NOVA retains its own HUD. Effects automatically enable when the humanoid view opens, and its original assembly soundtrack starts once the local audio context is running. Browser autoplay permissions still apply. There is no separate Assemble/Effects/Volume control strip. The clock/weather/history overview and preview selector appear only on the core HUD. The main dock and persona switch fade out in humanoid view; hover their usual positions or focus them using the keyboard to reveal them and return to the HUD.

The parent sends listening, thinking and speaking states, plus the actual microphone and Fish Audio playback amplitude, into the renderer. Preview selectors change expressions without fabricating speech audio. The assistant's existing chat panel, voice player and microphone remain the source of interaction. The iframe never opens its own microphone or camera. Mouse attention tracking comes from the supplied renderer; camera gestures are unavailable in this integration.

The renderer is served locally in a sandboxed iframe with scripts enabled and same-origin access disabled. Its content policy blocks network connections and allows only embedded image data/blob assets. Only bounded visual levels, a whitelisted state and effects controls cross the bridge; no credentials, conversation text or backend access are supplied. The supplied bundled React/Three renderer is kept separate from the Next.js application's dependency tree. Its embedded vendor license notices remain intact.

System-check shockwave now uses the original Tripod 52 Hz horn, supplied distortion/formants/compressor/reverb, and the original 41 Hz bass tail. Horn duration is 3.2 seconds; tail starts after 2.304 seconds and lasts 2.6 seconds. Output is connected through the existing HUD effects gain so mute, volume, Fish Audio speech ducking and cleanup still apply. Local synthesis uses no cloud API.

Files: `components/ApexHumanoid.tsx`, `components/apex-humanoid.css`, `public/humanoid/apex-entity.html`, `lib/original-horn.mjs`, `lib/system-check-sounds.mjs`, and the toggle in `components/HudPreview.tsx`. `scripts/import-humanoid.mjs` records the adaptation; regenerate from the original HTML only after reviewing changes. The reference contains bundled source and embedded face assets rather than a separate editable 3D mesh.

Run `npm.cmd run build`, then `npm.cmd start` alongside the existing `npm.cmd run runtime`. Open the face button, then open Conversation to talk. Test synthesis scheduling without audio/network calls using `node --test tests/original-horn.test.mjs`. This verifies Web Audio calls against a fixture; listening to the browser's local sound is a separate check. No paid voice/model test is required for visual preview.

## Chat activity correction

The face now follows pending chat requests and live APEX task/loop execution. Microphone/audio idle callbacks cannot clear Thinking while a reply is pending. Queued/running tasks keep Thinking after their acknowledgment; blocked/completed tasks do not. Listening and speaking take priority. The host exposes `data-activity` and the iframe exposes `data-apex-phase` for verifying the actual bridge.

Validation: 154 automated tests and production build passed. Mock-only browser verification on port 8089 confirmed pending reply + typing remains Thinking, background work remains Thinking after acknowledgment, and completion returns to Idle.
