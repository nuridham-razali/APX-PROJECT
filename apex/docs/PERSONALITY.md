# APEX personality equalizer

Open the Personality dock button. In humanoid mode, hover near the bottom-right dock or use keyboard focus to reveal it. Five segment columns set integer levels 1-5; click/tap a segment, or focus its slider and use arrows, Page Up/Down, Home or End. Close and reopen without resetting. Settings live in the existing runtime SQLite store under configuration/apex-personality, not browser-only sliders. The runtime must be running.

Presets (Sarcasm/Rough/Direct/Warmth/Push): Default 2/1/3/3/2; TARS 5/2/4/2/3; Sergeant 1/5/5/1/5; Retriever 1/1/3/5/3; Board 1/2/5/2/4. Manual changes are Custom. Startup restores the saved profile. Defaults do not overwrite existing profiles.

Explicit top-level chat messages and final Deepgram utterances share a local parser: Apex, set sarcasm to five; turn down the roughness; be warmer; set directness to maximum; switch to TARS mode; reset your personality; what are your personality settings? Relative changes are one level unless an amount is supplied. Values clamp to 1-5. Quoted text, compound requests and source-bearing sentences are not commands. Files, websites and model output never enter the settings parser. Unsupported phrasing remains ordinary conversation.

Each new APEX Gemini or Ollama request receives the validated backend instruction block. Client-supplied legacy personality fields cannot override it. Active requests retain their original snapshot, and profile updates do not stop current speech. Specialist instructions retain their role and tool boundaries; multi-role synthesis applies user-facing style. Native calculation and memory receipts remain literal. NOVA keeps its existing persona. Style never grants permissions or conceals uncertainty; distress and serious safety-sensitive conversations call for less sarcasm and roughness. TARS uses original humour rather than film dialogue.

Fish Audio model, voice ID and supported delivery parameters are unchanged. This feature changes response wording; it does not promise unsupported pitch or emotional voice control. Existing chat stays mounted when the equalizer opens. No model or Fish Audio request is generated by segment/preset clicks.

Test personality uses the fixed question: I keep putting off an important project. What should I do next? The confirmation identifies the selected provider. Choosing Generate sample runs one model response; Gemini may consume paid API quota. The sample is text-only and does not call Fish Audio. Cancel test makes no request. Model adherence remains probabilistic.

## Changed files
- lib/personality.mjs: shared validation, five controls, presets, command parser, style instructions.
- components/PersonalityEqualizer.tsx and personality-equalizer.css: compact accessible panel, persistence/events, sample consent.
- components/HudPreview.tsx: floating panel and retained conversation mounting.
- components/HudWorkPanel.tsx: local commands and immediate configuration updates without stopping speech.
- runtime/engine.mjs: persisted configuration, revision checks, local chat commands, per-request instructions.
- runtime/server.mjs and lib/runtime-proxy.ts: authenticated personality endpoint with existing origin protection.
- runtime/provider.mjs: removes conflicting legacy APEX tone controls, preserves NOVA and provider selection.
- runtime/agent-execution.mjs and runtime/task-loop.mjs: final versus internal communication scope.
- components/ShaderBackground.jsx: speaking-state animation only, upstream 3.4x speaking flow; removed audio-envelope dependence. HudPreview no longer supplies audio amplitude to plasma. Existing thin cyan/gold lines and traveling highlights stay intact; system-check scanning animation remains.
- tests/personality.test.mjs and tests/http.integration.mjs: validation, parser, persistence, instructions, HTTP permissions and revisions.

## Verification
Production build passed; 130 automated tests passed. Personality model tests use injected fixtures, including a mocked Gemini HTTP request, not live Gemini responses. Real isolated local HTTP tests passed authenticated updates, malformed-action rejection, stale revisions, cross-origin rejection, local commands without a configured model, and state propagation. Browser checks exercised five columns, presets, keyboard controls, close/reopen, chat command updates and reload persistence. No paid model, Fish Audio or Deepgram tests were run. Speech recognition and voice delivery are covered by existing fixtures, not newly verified live transcription. Optional comparison is available for the user.

## Run
From the apex directory, run npm.cmd run runtime in one terminal and npm.cmd start in another after npm.cmd run build; or use the existing Start.bat. Open http://127.0.0.1:3000/. Keep existing private environment settings unchanged.
