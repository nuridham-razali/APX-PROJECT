APEX's authenticated local runtime handles these explicit voice/chat commands without a Gemini call:

- `Open Chrome`, `Open Edge`, `Open Notepad`, `Open Calculator`, `Open terminal`, `Open File Explorer`, `Open media player` (the application must be installed).
- `Check running processes`: actual top 15 Windows processes by working set.
- `Search the web for Kubernetes`, `Play jazz on YouTube`, `Directions to Gurun, Kedah`.
- `Open YouTube`, `Open Google Maps` open their homepages.
- `Open YouTube and play Naruto Shippuden opening Blue Bird`, `Play Blue Bird on YouTube`: APEX opens its dedicated media browser, selects the first normal video result and verifies audible playback advancing, excluding adverts. The reply names the actual selected video.
- `Fullscreen`, `Make it full screen`, `Exit fullscreen`, `Pause the video`, `Resume the video` control that same APEX-owned video. You can also say `Play Blue Bird on YouTube in fullscreen`.
- `Draft email to name@example.com subject: Meeting body: Can we meet tomorrow?`
- `Check my schedule`, `Check my schedule limit 5`: upcoming seven days from the connected Google Calendar, bounded to 1–50 entries.

The internal tool names are SYSTEM_CONTROL, BROWSER_NAVIGATE, YOUTUBE_CONTROL, DRAFT_EMAIL and CHECK_CALENDAR. The response API includes the tool name and real receipt; the agent map records execution start, completion and failure. Conversation history and Fish Audio speech use the normal response pipeline.

Applications use a fixed executable allowlist with no shell interpolation. Browser requests use fixed Google, YouTube and Maps HTTPS origins with URL-encoded queries. A submitted OS launch is a receipt for the launch request, not independent verification that a window rendered. YouTube search commands open results; play commands execute the verified media controller. No arbitrary scripts, executable paths, file deletion, system-setting changes or unconfirmed sending are added.

Email drafts are stored locally with recipient, subject, body and `sent:false`; they do not require Gmail credentials. Incomplete commands ask for explicit fields rather than guessing addresses or content. Sending continues to use the existing Email node's exact payload approval and Gmail adapter, requiring backend credentials. Calendar access requires Google sign-in; missing credentials report Not configured.

Quoted commands, bracketed tool strings, model replies, memory and external document content cannot trigger this router. These declarations do not grant capabilities through text: actual handlers determine what can execute. NOVA's existing background task routing is retained.

Browser launches now select an installed Chrome or Edge executable and use Windows Start-Process with a new-window argument. Explorer URL delegation has been removed. Arguments are passed as environment data to fixed launcher code, never interpolated into scripts. Desktop automation requires running the runtime in the signed-in user's Windows desktop session; use Start.bat locally. A coding sandbox or headless/cloud host cannot establish a visible desktop window merely from a successful spawn receipt.

Media automation uses Playwright Core with installed Chrome/Edge, a dedicated `.apex-data/media-browser` profile and Chromium sandboxing enabled. It does not attach to your normal browser, expose a remote debugging port, or execute instructions from pages. Only YouTube selection, playback, pause/resume and fullscreen are implemented. Closing that browser requires a new play command before media controls can work again. Failed playback, consent/sign-in prompts, timeouts and missing sessions return errors, never successful playback claims. Cancelled or timed-out media operations close their owned page.

Conversational lead-ins such as `Nah, play Love Yourself on YouTube` and `Okay Apex, can you please play Blue Bird` route locally. Negation, quoted commands and instructions embedded in documents remain excluded. Verified media receipts are saved per conversation and supplied as historical backend evidence in later model requests; they do not assert that a video is still playing.
